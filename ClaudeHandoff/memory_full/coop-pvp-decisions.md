On 2026-10-06 the user said «давай приступим к кооп+пвп» and asked for a project analysis, a to-do list and clarifying questions. I sent the analysis, a phased plan (0 prep → 1 network foundation → co-op → PvP) and a 26-question form with ★ defaults. Answers:

**Order and tech**
- Co-op FIRST, then PvP. This overrides «PvP Классика first as the network foundation» from [[game-design-decisions]].
- Netcode for GameObjects + Unity Multiplayer Services (Relay + Lobby), room by code. The project is already linked to Unity Cloud (org begod24, cloudProjectId 28ca9706-…); the user has to enable Relay/Lobby in the Dashboard.
- Release: closed tests with friends first; online goes to itch only when BOTH co-op and PvP are ready.
- Menu: «Играть» → Одному / Вместе / Друг против друга → create room or join by code → lobby screen (code, players with kids and nicknames, «Готов», host starts). The yard hub stays for later.
- Authority: each player's own movement is decided by their own computer (owner-authoritative, cheating is possible); balls, hits and catches are decided by the host.
- Catch timing online: «прав ловящий». Catch windows are NOT widened. Follow-up (same day): hits AND catches on a player are judged by that player's own computer against what it sees (the host checks the ball really was near); this replaces «host rewinds the ball» and «host decides hits». The host still simulates the balls themselves.
- Local couch co-op later, but write the code with several local players in mind from the start.

**PvP «Классика»**
- Played on the run arenas, picked in the lobby (not a separate chalk court or gym). How exactly the court sits on an arena was asked as a follow-up.
- No crossing the centre line (an invisible wall on the chalk line). Edges: boards or a net, and a hit after bouncing off the board counts.
- Balls: 1×1 has one ball; team modes have one ball per two players. Round start: balls on the centre line, everyone runs for them on the whistle.
- 1×1: first to 7 points. After a hit there is a ~1 s pause with «очко», the ball goes back to the thrower's hands and everyone stays where they were.
- 2×2+: an out player stands behind the opponents and can throw from there. If they knock someone out, they come back. A catch still knocks the thrower out and brings a teammate back. A team match is first to 3 round wins (best of 5).
- First modes: 1×1 and 2×2 only.
- Kept from solo: charged throw; a strong ball knocks the ball out of the hands without a perfect catch; catching only from the front; «свечка» — if the ball popping off a body is caught before it lands (by the hit player or a teammate), the hit doesn't count. NOT picked: dash (no dash in PvP), tackle.

**Co-op**
- Coins: shared loot with personal wallets (whoever picks a coin up, everyone gets the same; each player spends their own).
- Kiosk: each player has their own showcase, several can be open at once, time doesn't stop.
- Portfolio picked up mid-fight goes into a backpack; the player opens it with a button whenever they want. If it is still unopened when the arena is cleared, it opens then.
- An ally's ball passes through teammates; pressing catch catches it (that is the pass).
- Fork: the group votes with their feet. The run moves on when every living player stands at the same arrow.
- Danger: the host picks from the levels they have unlocked; a win unlocks the next level for every participant.
- Each kid only once per room (NOT duplicates). There are 4 kids, so this caps PvP at 2×2 until more kids exist.
- Final «Мама зовёт домой»: the run is won when all living players reach the door; downed players count too.
- User's note: the co-op economy and card balance must be reworked so that 2–4 players with different cards don't breeze through arenas 2–3. My diagnosis: with personal wallets each player builds a full solo build (team power ≈ N×), while enemies got only +50% hits per player (×2.5 for 4).
- Co-op balance (follow-up, same day):
  - Coins: shares. Loot stays shared, but each player gets 70% / 55% / 45% of the solo amount with 2 / 3 / 4 players (team total ×1.4 / ×1.65 / ×1.8).
  - Cards: fewer pockets (5 with 2–3 players, 4 with 4; solo 6); one gold card per TEAM (after anyone takes a gold, nobody is offered gold). The boss card stays one per player.
  - Enemies: all four picked. Toughness per extra player grows by arena: +50% hits on arena 1, +65% on arena 2, +80% on arena 3 (4 players: ×2.5 → ×3 → ×3.4); enemies spread attention (some go for a player nobody is chasing); +1 elite per arena for every second extra player (still only one portfolio); bosses use abilities more often with more players.
- PvP court (follow-up): a chalk court with a net inside the chosen run arena, sized by mode (1×1 ~16×10 m, 2×2 ~22×14 m); props outside the court are decor; on dark arenas lamps hang over the court.

**My defaults (sent, user didn't object):** host leaves → everyone goes to the menu; a dropped client's kid disappears; join only at the start; Esc doesn't pause online; up to 4 in co-op; nickname typed once + chalk circle in the team colour; enemy hits per player count (superseded by the per-arena growth above); revive = hold 2 s, the revived player gets 1 heart; separate co-op records, tutorial solo-only, bestiary per player; co-op pass cards get their own Q&A once basic co-op works.

**Smoothness rework (2026-10-06, after the user's К1–К3 test: «телепортации, всё прерывисто с игроками и анимациями»):**
- Diagnosis: (1) the owner sent nothing when stopping (only 0.2 s keepalive) → others extrapolated past the stop and snapped back; (2) sample clock = NGO HostNow, which NGO time sync keeps adjusting, and the adaptive delay grew at 0.5 s/s → playback sped up/slowed down; (3) remote animation speed from per-frame position delta (noisy); (4) pose (dash/catch/charge) went via a NetworkVariable, out of step with the delayed position; (5) tangents from Motor.Velocity (intent), not real movement (walls); plus MPPM virtual players are throttled background processes.
- `Net/NetMotion.cs` MotionBuffer rewritten: samples stamped with the SENDER's `Time.unscaledTimeAsDouble`, receiver maps by the fastest-arrival floor (rises 0.03 s/s) + jitter (fast attack/slow release); render clock rate limited to ±8%, resync >0.3 s; delay = interval + 1.5·jitter + 15 ms (35–350 ms); extrapolation 0.2 s decelerating; correction blend 0.12 s, snap >4 m. Debug: Delay/Jitter/StarvedShare/Snaps shown per remote player on F3 (NetStatsOverlay).
- NetPlayer: MotionSample carries NetPose (3-byte payload), real velocity (`PlayerMotor.ActualVelocity`, scripted → frame delta), sends immediately on stop and on pose change, sends a «still standing» point before starting to run; `_pose` NetworkVariable removed. `PlayerController.RemoteVelocity` feeds KidAnimator; dash trail uses Action. NetEnemies stamps with host local time and also send on stop.
